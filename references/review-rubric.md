# Review Rubric

按文档类型选择最相关的清单，不要机械套用全部条目。

## 通用检查

| 维度 | 检查点 |
|------|--------|
| 目标 | 是否说清要解决什么问题；是否混入非目标 |
| 受众 | 是否适合目标读者；是否需要解释背景 |
| 范围 | 是否明确包含/不包含的系统、接口、环境、时间窗口 |
| 术语 | 同一概念是否使用同一名称；中英缩写是否解释 |
| 数字 | 数量、时间、比例、阈值是否有单位和口径 |
| 表格 | 列名是否完整；同类表格列是否一致；空单元格是否可解释 |
| 步骤 | 前置条件、执行步骤、验证步骤是否闭环 |
| 结论 | 结论是否由数据或步骤支撑；是否过度承诺 |
| 风险 | 是否说明失败路径、降级、回滚、排查入口 |

## 技术方案

| 维度 | 检查点 |
|------|--------|
| 背景 | 是否说明现状问题、触发原因和约束 |
| 方案边界 | 是否明确不改什么、不覆盖什么、不承诺什么 |
| 架构 | 调用链、模块职责、数据流是否清楚 |
| 接口 | 入参、出参、错误、鉴权、兼容性是否明确 |
| 数据 | 数据来源、存储、迁移、幂等、并发一致性是否说明 |
| 异常 | 超时、重试、部分失败、重复请求、并发冲突是否覆盖 |
| 测试 | 单测、集成、契约、回归、灰度验证是否匹配风险 |
| 兼容 | 老版本、上下游、配置默认值、回滚兼容是否明确 |

## 压测方案

| 维度 | 检查点 |
|------|--------|
| 场景 | 基准、低并发、高并发、边界、混合负载是否区分 |
| 负载口径 | 总请求数、并发语义、worker 分配、持续时间是否明确 |
| 指标 | 成功率、P99、Avg、吞吐、失败数、Timeout、Rejected 是否定义 |
| 阈值 | 哪些是验收项，哪些是观察项，是否有明确通过线 |
| 环境 | 服务版本、硬件拓扑、配置、网络、数据规模是否记录 |
| 数据隔离 | 卡号、账号、租户、缓存、历史数据是否隔离 |
| 失败归因 | 是否要求 errorReason、errorStage、per-target breakdown |
| 边界探测 | 是否用算法或步骤替代“？”、“尽量高”等模糊表达 |
| 压测后复核 | 是否检查状态残留、资源释放、数据清理 |

## 上线文档

| 维度 | 检查点 |
|------|--------|
| 前置条件 | 版本、配置、依赖、权限、窗口期、备份是否齐全 |
| 步骤 | 每一步是否可执行、可观测、可回退 |
| 验证 | 上线前、上线中、上线后验证项是否明确 |
| 监控 | 关键指标、阈值、告警、日志入口是否说明 |
| 回滚 | 触发条件、执行步骤、数据兼容、负责人是否明确 |
| 风险 | 已知风险、影响范围、通知机制是否清楚 |

## 汇报文档

| 维度 | 检查点 |
|------|--------|
| 结论先行 | 开头是否给出可被管理层理解的结论 |
| 数据支撑 | 每个结论是否有数据、对比或事实依据 |
| 口径一致 | 指标名、单位、时间范围是否前后一致 |
| 重点突出 | 是否区分成果、风险、待决策事项 |
| 追问准备 | 容易被问到的“为什么、凭什么、风险在哪”是否提前回答 |
| 表达克制 | 是否避免绝对化、夸大或无法证明的说法 |

## 复盘文档

| 维度 | 检查点 |
|------|--------|
| 事实/推测 | 是否分清事实、判断、猜测 |
| 时间线 | 关键事件是否有时间、责任方和证据 |
| 根因 | 是否追到机制问题，而不只停留在表象 |
| 影响 | 影响范围、持续时间、用户影响是否量化 |
| 改进项 | 是否可执行、有负责人、有截止时间、有验证方式 |
| 防复发 | 是否能证明改进项可以降低同类风险 |

## PR 或变更说明

| 维度 | 检查点 |
|------|--------|
| 变更范围 | 改了什么、没改什么是否明确 |
| 行为变化 | 对用户、接口、配置、性能、兼容性的影响是否说明 |
| 测试结果 | 命令、环境、失败项、未跑原因是否清楚 |
| 风险 | 回滚方式、灰度策略、监控项是否明确 |
