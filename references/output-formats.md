# Output Formats

## 默认审校输出

```markdown
**审校结论**
整体可用/需要调整/不建议直接对外。最主要风险是：...

| 位置 | 级别 | 问题 | 为什么有风险 | 建议改法 |
|------|------|------|--------------|----------|
| ... | P1 | ... | ... | ... |

**建议优先处理**
1. ...
2. ...
```

## 用户要求“不新增内容”

```markdown
未发现需要新增方案的缺口。仅从错别字、语义清晰度和一致性看，建议调整：

| 原文 | 问题 | 建议替换 |
|------|------|----------|
| ... | ... | ... |
```

## 用户要求“查漏补缺”

```markdown
**主要缺口**

| 级别 | 缺口 | 影响 | 建议补充 |
|------|------|------|----------|
| P0 | ... | ... | ... |

**可保留不改**
- ...
```

## 用户要求“汇报前检查”

```markdown
**汇报风险**

| 可能被问到的问题 | 当前文档是否回答 | 建议准备的话术/数据 |
|------------------|------------------|---------------------|
| ... | 否 | ... |
```

## 用户要求“直接修订”

```markdown
已按以下原则修订：
- 保留原方案边界
- 只修复语义和逻辑表达
- 未新增未确认的事实

修订版：
...
```

## 常用措辞

| 场景 | 推荐措辞 |
|------|----------|
| 事实不确定 | “这里需要标注数据来源或写成待核实，否则评审时容易被追问。” |
| 指标不清 | “该指标缺少口径，读者无法判断结果是否通过。” |
| 逻辑跳跃 | “从前文无法推出该结论，需要补充依据或降低表述强度。” |
| 用户限制不新增 | “在不新增内容的前提下，建议仅替换为...” |
| 发现严重风险 | “这不是措辞问题，而是验收/执行口径会产生误判。” |

## 严重程度措辞

| 级别 | 开头建议 |
|------|----------|
| P0 | “这个点会直接影响结论/上线判断，建议先改。” |
| P1 | “这个点评审时大概率会被追问。” |
| P2 | “这个点不影响主结论，但会造成理解成本。” |
| P3 | “格式和表述可统一。” |
